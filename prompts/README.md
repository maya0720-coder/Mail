# 역할별 프롬프트 안내

## 실행 순서

`main_prompt`는 공통 조정 지침이며, 앱은 `main_prompt + common.md + 현재 역할`을 조합합니다.

| 요청 | 실행 순서 | 실행 방식 |
|---|---|---|
| 구현·개선 | dev_product → dev_architect → 구현 → dev_qa | 코딩 에이전트가 main_prompt를 읽고 수행 |
| 수집 | 코드 수집·범위 검사 → 01_analyze → 03_verify → 02_reconcile → 제안 저장 → 04_wiki | Python 파이프라인 |
| 업무 승인·수정 | 사용자 확인 → 트랜잭션 저장 → 04_wiki | 앱 화면/API |
| 검색 | 키워드 검색 → 스레드 확장 → 05_search | 검색 화면/CLI |
| 보고 | 이벤트 재생·집계 → 06_report → 보고서 저장 | 보고 화면/CLI |
| 일자별 업무 히스토리 | 청크 색인 → BM25·토픽 확장 → 07_history → 근거·날짜별 타임라인 | 업무 히스토리 화면 |
| 해결 방안 | 업무 실제 출처·대화 확장 → 07_solution → 근거 ID 검사 → 제안 저장 | 업무·토픽 펼치기 화면 |

검증 역할의 번호보다 실제 실행 순서가 우선합니다. 근거 검증을 통과한 후보만 업무 연결 단계에 넘깁니다. 연결은 제안이며 사용자가 최종 대상을 확인합니다.

## 역할 계약

| 파일 | 입력 | 출력 |
|---|---|---|
| 01_analyze.md | 사용자 주소, 메일 한 건 | summary, tasks |
| 03_verify.md | 메일, 추출 결과 | verdict, issues |
| 02_reconcile.md | 추출 결과, 같은 스레드 업무 | links |
| 04_wiki.md | 현재 업무, 승인 대기 목록 | 프로젝트별 해설 |
| 05_search.md | 질문, 검색된 원문·이벤트 | 답변, 타임라인, 근거, 미확인 사항 |
| 06_report.md | 기간, 확정 집계·업무·이벤트 | 성과·위험·다음 주 제안 |
| 07_history.md | 질문, 검색된 날짜별 청크·출처 ID | 근거 답변·인용 ID·미확인 사항 |

`engine=rules`는 프롬프트를 읽고 해시를 남기지만 LLM 호출 없이 코드의 결정 규칙을 사용합니다. `engine=ollama`에서 실제 역할별 LLM 호출이 순차 실행됩니다. 프롬프트만 저장했다고 AI가 실행되는 것은 아닙니다.

## 메인 프롬프트 사용 예

코딩 에이전트에게 다음처럼 요청하세요.

> 이 프로젝트의 main_prompt를 읽고, 현재 구현과 docs/검증결과.md를 확인한 뒤 내가 지정한 개선 작업을 수행해줘. 기존 데이터는 보존하고 테스트와 실행가이드를 함께 갱신해줘.

앱을 사용하는 경우에는 프롬프트를 매번 복사할 필요가 없습니다. `python app.py serve` 또는 `collect/import/search/report` 명령이 해당 흐름을 실행합니다.
