# Teams 수집 제외·업무 상태·삭제·필터

## 수집 제외

`no-reply@teams.mail.microsoft`는 기본 수집 제외 발신자입니다. 표시 이름이 아닌 실제 이메일 주소를 대소문자 구분 없이 비교합니다. Outlook에서는 새 메일의 본문을 읽기 전에 제외하고, 파일 가져오기에서도 분석·저장 전에 제외합니다.

설정의 `excluded_senders`에 추가 주소를 넣을 수 있습니다. 요청한 Teams 주소는 기본 규칙에도 등록했습니다.

기존 수집본 중 해당 발신자 3건은 `excluded=1`로 표시했습니다. 원문 409건은 유지하고, 목록·토픽·검색·RAG의 메일 근거·미승인 업무 후보·새 보고서의 메일 요약에서 제외합니다. 이미 사용자가 승인한 업무와 과거 보고서는 자동 삭제하지 않습니다.

## 업무 상태

| 상태 | 의미 |
|---|---|
| 미등록 | 작업 등록 전 검토 상태 |
| 등록완료 | 등록했고 아직 착수하지 않은 상태 |
| 진행중 | 작업을 수행 중인 상태 |
| 대기 | 회신·승인·외부 작업을 기다리는 상태 |
| 완료 | 수행 완료를 사용자가 확인한 상태 |
| 취소 | 진행하지 않기로 결정한 상태 |

새 업무 제안을 승인하면 등록완료로 생성합니다. 기존 할일은 등록완료, 확인필요는 미등록으로 표시합니다. 이전 변경 이벤트의 원본 JSON은 수정하지 않습니다.

**완료 처리**를 누르면 상태와 완료 시각을 함께 저장합니다. 완료 상태에서 기한 등 다른 값을 바꿔도 완료 시각은 유지합니다. **다시 진행**을 누르면 진행중으로 바꾸고 현재 완료 시각을 비웁니다. 이전 완료 기록은 변경 이력과 RAG 히스토리에 남습니다. 재완료하면 새 완료 시각을 기록합니다.

기존 완료 건은 실제 완료 전이 이벤트에서 시각을 복원합니다. 근거가 없으면 임의로 날짜를 만들지 않고 완료 시각 미확인으로 표시합니다.

## 삭제와 복원

**삭제**는 휴지통으로 이동하는 방식입니다. 일반 목록·현재 업무 집계·새 보고서 집계에서 제외하고 원문과 변경 이력은 보존합니다. 목록 범위를 휴지통으로 바꾸면 **복원**할 수 있습니다. 완료 업무를 삭제·복원해도 상태와 완료 시각을 유지합니다.

휴지통 업무는 수정하거나 새 메일 변경 대상으로 연결할 수 없습니다. 먼저 복원해야 합니다. 과거 보고 기간은 당시 이벤트 상태로 복원하므로 삭제 전의 이력도 조회할 수 있습니다.

## 내 업무 필터

- 업무 검색: 업무명·프로젝트·담당자에서 부분 검색.
- 상태: 요청한 4개 상태와 대기·취소, 또는 전체.
- 프로젝트: 지정 프로젝트만 조회.
- 목록 범위: 일반 업무 또는 휴지통.
- 완료일 시작·종료: 완료 시각이 해당 날짜 범위에 있는 업무만 조회. 종료일 포함, KST 기준.
- 필터 초기화: 모든 조건을 비우고 일반 업무로 복귀.

상태별 숫자는 선택한 목록 범위 전체의 건수입니다. 검색어·기간 등을 조합한 결과 건수는 오른쪽의 선택 조건 건수로 표시합니다.

## 메뉴 설명 토스트

확인함, 내 업무, 수집한 메일, 근거 검색, 업무 히스토리, 주간 보고, 변경 이력, 처리 로그 메뉴를 누르면 짧은 기능 설명이 오른쪽 아래에 약 4초 동안 나타납니다. 실행 오류나 작업 결과 안내와는 별도로 표시합니다.

## 실행·검증

이전 서버를 종료하고 `run.bat`을 실행한 다음 브라우저를 새로고침하세요. 기존 DB에는 제외 여부·완료 시각·삭제 시각 컬럼을 추가합니다. 원문과 기존 이력은 삭제하지 않습니다.

테스트는 `python -m unittest discover -s tests -v`로 실행합니다. 실제 개인 업무를 완료·삭제하는 테스트는 수행하지 않았으며, 화면 조작은 `config.demo.json`의 가상 자료에서 확인했습니다.
