# 검증 결과와 남은 연결 작업

검증일: 2026-11-04. 환경: Windows, Python 3.12.14, 기본 rules 엔진.

## 자동 테스트

명령: `.venv\Scripts\python.exe -m unittest discover -s tests -v`

**77개 테스트 통과.** Windows Outlook 수집에는 pywin32, PDF 보고 생성에는 reportlab이 필요하며 현재 가상환경에 설치했습니다. 테스트는 실제 Outlook에 접근하지 않습니다. 코드 컴파일 검사와 JavaScript 구문 검사도 통과했습니다.

## 수집 제외·업무 관리 검증

- Teams 실제 주소의 대소문자·표시 이름 처리, 비슷한 다른 주소를 차단하지 않는지 확인했습니다.
- Outlook에서 제외 발신자의 본문을 읽지 않는지, 가져오기에서 모델 호출·저장을 건너뛰는지 검증했습니다.
- 기존 Teams 알림 3건을 숨기고 원문 409건을 보존했습니다. 기존 할일 1건은 등록완료로 전환했습니다.
- 요청 상태와 대기·취소, 완료 시각 기록·유지·재개, 삭제·복원·원문 보존을 검증했습니다.
- 삭제 업무 연결 차단, 상태·프로젝트·검색어·완료일·휴지통 복합 필터, 과거 시점 보고 복원을 검증했습니다.
- API와 가상 데이터 브라우저에서 완료 → 삭제 → 휴지통 → 복원 → 완료일 필터 → 재개 → 재완료 흐름을 확인했습니다.
- 메뉴 선택 시 설명 토스트 표시를 확인했습니다. 실제 사용자 업무를 임의로 완료·삭제하지 않았습니다.

## 토픽·일자별 RAG·PDF 추가 검증

- 변경 전 `backups/v0.1`을 만들고 52개 파일의 SHA-256을 재검증했습니다. 백업 DB 무결성 검사를 통과했습니다.
- 기존 본문 409건과 승인 대기 후보를 보존한 채 213개 토픽으로 묶었습니다. 기존 409건의 수신 시각 메타데이터도 보완했습니다.
- 반복 외부메일·회신 접두어, 끊어진 스레드 ID의 동일 제목, 짧은 공통 제목 분리, 수신일 우선 정렬을 검증했습니다.
- 원문 보존과 인용문을 제외한 하위 요약, 신규 메일·업무 이벤트의 일자별 검색, 기간 밖 토픽 확장 차단, 동의어 검색을 검증했습니다.
- 로컬 FTS5 청크 색인의 재사용·갱신, 허위 근거 ID를 인용하는 생성형 답변 거부를 검증했습니다.
- 참조 4열·7구분 보고 구조, 미래 메일 제외, 미승인 메일의 완료 오인 방지, 인증 알림 제외, PDF 다운로드 API를 검증했습니다.
- 실제 브라우저에서 토픽 펼치기 → 하위 메일 원문 보기 → RAG 질문과 날짜별 결과를 확인했습니다.
- 실제 수집 자료로 주간보고 초안을 생성하고 PDF 페이지를 렌더링해 한글·표·줄바꿈·페이지 머리글을 확인했습니다. LLM 없이 생성한 추출형 초안이며 자동 분류·요약은 검토 후 확정합니다.

## 실제 Outlook 연동 검증 — 2026-11-04

- 현재 PC의 AD 환경 변수에서 `GFZ\\maya0720`을 확인하고 `maya0720@golfzon.com`을 기본 주소로 설정했습니다.
- Classic Outlook에 설치된 본인 계정의 연결과 받은편지함 접근을 확인했습니다.
- 최근 30일의 수신 시각 범위에서 본인 수신/참조 메일 409건을 `data/golfzon/`에 저장했습니다.
- 첫 수집 중 7개 긴 메일이 후보 제한으로 실패한 것을 확인해, 원문 보존·명시적인 후보 제한 안내로 수정한 뒤 7건 모두 재수집했습니다.
- 앱 시작에 따른 자동 수집을 확인했습니다. 기간 내 항목 478개에서 기존 본문 재수집 없이 추가 저장 0건, 실패 0건으로 완료했습니다.
- 날짜 필터는 Outlook Restrict에 먼저 적용합니다. 기본 최근 30일, 지정 종료일 포함, UTC 변환, 부분 날짜 거부, 중복·기간 밖·타인 메일의 본문 미조회 테스트를 추가했습니다.
- 자동 작업 시작, 요청 중복 거부, API 기간 입력과 정적 자원 응답을 검증했습니다.
- 공유 사서함과 다른 계정의 본문은 수집하지 않았습니다. 본인 To/Cc가 없는 배포목록 메일은 제외될 수 있습니다.

실제 메일을 보여주는 확인함의 제안은 아직 승인하지 않았습니다. 규칙 모드는 문맥에 따라 과도한 후보를 만들 수 있으므로 AI 의미 분석이 필요한 경우 로컬 Ollama를 설정하고 결과를 검토해야 합니다.

검증한 범위:

- 동일 메일 재수집의 중복 방지, 같은 ID의 변경 원문 거부.
- 본인 아닌 수신자 거부, 참조된 타인 업무 제외, 불명확 담당자 유지.
- 사용자 승인 전 업무 미생성, 승인 중복 방지, 제안 제외.
- 일정 변경 승인, 대상 없는 변경 거부, 사용자 수정 자동 덮어쓰기 방지.
- 취소·완료 반영, "완료해주세요"와 완료 사실 구분.
- 원문에 없는 근거와 유효하지 않은 날짜 거부.
- 원문 날짜의 시간대 검사, 한글 EML과 스레드 파싱.
- 키워드 검색 후 관련 스레드 확장과 업무 이력 연결.
- 완료 중복 집계 방지, 재개된 업무 제외, 과거 시점 업무 상태 복원.
- 모델 오류 시 자동 규칙 모드 전환 방지, 실행 실패 기록.
- 역할 순서와 프롬프트 SHA-256 해시 기록.
- 데이터 폴더를 한 계정에 연결하고 다른 계정으로 재사용할 때 거부.
- API 토큰, 호스트 경계, 외부 Origin 쓰기 거부, HTTP 입력 오류 처리.

## 실제 브라우저 점검

로컬 웹 화면에서 다음 흐름을 수행했습니다.

1. 가상 메일 5건 수집 → 제안 3건.
2. 알파 신규 업무 승인, 기존 업무 선택 후 일정 변경 승인.
3. 베타 신규 업무 승인 후 완료 처리.
4. `협력사` 검색 → 최초 요청·변경 메일·업무 이벤트 확인.
5. 최근 7일 보고 생성 → 완료 1건, 진행 1건, 기한 경과 0건 확인.

화면은 한국어로 정상 표시됐으며 초기 화면 예시는 [기존 실행 화면](화면예시.png)에 보관했습니다. 이번 디자인 개편은 별도 `config.demo.json`·`data/demo/`의 가상 메일로 확인했습니다. 새 확인함에서 신규 업무 승인과 변경 업무 연결을 확인했고, 실제 회사 메일과 분리했습니다. 새 화면 예시는 [개편 디자인](디자인예시.png)에 보관합니다.

## 아직 검증하지 않은 범위

| 범위 | 이유와 필요한 작업 |
|---|---|
| Outlook 하위 폴더·공유 사서함 | 수집 범위에 포함하지 않음. 본인 받은편지함만 구현 |
| 회사 그룹웨어·Outlook 웹 수집 | 사이트 정보·DOM·로그인이 없음. 선택자와 날짜 형식 조정 필요 |
| Ollama 실제 모델 분석 | 로컬 모델을 설치·실행하지 않음. 모델별 JSON 응답과 한국어 업무 추출 품질 평가 필요 |
| 예약 보고 실행 | 운영체제 예약 작업을 자동 등록하지 않음. 가이드에 따라 사용자 계정으로 설정 필요 |
| 장기간 대용량 운용 | 실제 30일 메일 수집까지 확인. 날짜별 수동 조회와 단일 수집 작업은 구현, 다중 사용자 운용은 미검증 |

## 제공하지 않는 기능

첨부파일 분석, 화면 OCR, New Outlook COM, 그룹웨어 공통 범용 선택자,
자동 페이지 넘김, 벡터 검색, GraphRAG, 완전자율 업무 확정,
메일 자동 발송, 외부 공개 호스팅, 다중 사용자 인증, 저장 암호화는 포함하지 않습니다.

현재 PC의 Classic Outlook 실계정 연결은 위 항목처럼 확인했습니다. 다른 PC·다른 Outlook 프로필·그룹웨어의 연결 성공까지 의미하지는 않습니다.
