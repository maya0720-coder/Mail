# 실행 및 운영 가이드

Teams 수집 제외와 새 업무 상태·휴지통·완료일 필터·메뉴 토스트는 [업무 관리 업데이트](업무상태_수집제외.md)를 확인하세요. 변경 후 `run.bat` 재실행과 브라우저 새로고침이 필요합니다.

최신 토픽 묶기·일자별 RAG 히스토리·PDF 보고서 사용법과 v0.1 백업 위치는 [토픽·RAG 업데이트 안내](토픽_RAG_업데이트.md)를 먼저 확인하세요.

## 현재 PC에서 바로 사용하기 — Outlook 실제 연동

2026-11-04에 `maya0720@golfzon.com` 연결과 실제 메일 409건 수집을 확인했습니다. 기존 실습 데이터는 `data/`에 남겨두고 실제 메일은 `data/golfzon/`에 보관합니다.

1. Classic Outlook을 본인 Windows 계정으로 엽니다.
2. 프로젝트의 `setup.bat`을 한 번 실행해 Python 3.11과 Outlook 의존 패키지를 준비합니다. 이어 `run.bat`을 실행합니다. 실행 배치 파일은 매번 설치 상태를 확인한 뒤 앱을 시작합니다. 이전 앱 서버가 켜져 있으면 종료한 뒤 다시 실행합니다.
3. <http://127.0.0.1:18765>를 엽니다. 앱 시작 시 최근 30일을 자동 수집하고, Outlook 새 메일 알림으로 들어오는 메일을 바로 수집합니다. 알림 누락을 대비해 실행 중 10분마다 다시 확인합니다.
4. 30일보다 오래된 메일은 상단 **기간 지정**에서 시작일·종료일을 입력하고 **지정 기간 수집**을 누릅니다.
5. 수집 중에도 화면을 사용할 수 있습니다. 완료되면 수집 건수와 마지막 확인 시각이 표시됩니다.
6. 확인함의 제안은 사용자 승인 후 업무에 반영됩니다. 많은 제안은 25건씩 표시합니다.

수집 기간은 **메일 수신 시각**을 기준으로 합니다. 기본 범위는 현재 시각부터 정확히 30일 전까지이고, 직접 지정한 날짜는 종료일을 포함합니다. 한 번의 수동 수집은 최대 366일이며 더 오래된 자료는 기간을 나눠 수집합니다. 지정 기간 밖의 본문은 조회하지 않습니다.

Outlook 연결에는 현재 로그인된 Outlook 프로필을 사용합니다. AD 계정명으로 메일 주소를 계산하는 것이며, 앱이 AD 비밀번호를 수집하거나 별도 로그인 인증을 대신하는 것은 아닙니다.

실제 설정:

```json
"user_email": "auto",
"identity_mode": "windows_ad",
"email_domain": "golfzon.com",
"data_dir": "data/golfzon",
"outlook_auto_sync": true,
"outlook_sync_minutes": 10
```

주소를 직접 입력하려면 `identity_mode`도 `manual`로 변경해야 합니다. 기존 사용자 데이터 폴더의 계정 연결은 유지됩니다.

별도 프롬프트 실행은 필요 없습니다. 앱이 `main_prompt`와 해당 역할 파일을 자동으로 읽습니다. `rules`는 기본 규칙 분석이고 LLM 호출이 아닙니다. 실제 AI 해설은 아래 8절의 로컬 Ollama 설정이 필요합니다.

화면 개편은 프로젝트에 가져온 `design-skills/frontend-design/SKILL.md`를 적용했습니다. 다음 작업에서도 이 파일을 읽어 같은 디자인 기준을 사용할 수 있습니다. [디자인 예시](디자인예시.png)와 [기간 지정 예시](기간지정예시.png)는 실제 회사 메일과 분리한 가상 데이터 화면입니다.

## 1. 준비

- Windows 10/11, Python 3.11 이상.
- 기본 앱·가상 메일·EML/JSON 가져오기: 추가 패키지 불필요.
- Classic Outlook 수집: 본인 프로필로 로그인된 Classic Outlook, pywin32.
- 그룹웨어 수집: Playwright Chromium, 본인 로그인, 사이트별 DOM 선택자 설정.
- AI 분석: PC에서 실행되는 Ollama와 사용자가 설치한 모델. 모델 설치에 필요한 메모리는 모델별로 확인합니다.

이 앱은 PC 안에서 실행되는 Python 프로그램과 브라우저 화면을 결합합니다. 외부 호스팅 서버를 설치할 필요가 없습니다.

## 2. 최초 설치

현재 작업 PC에는 `.venv`를 준비해 두었습니다. 이 PC에서는 `run.bat`으로 바로 시작할 수 있습니다. 아래 설치 과정은 새 PC 또는 가상환경을 다시 만드는 경우에 사용합니다.

PowerShell:

```powershell
cd D:\99.GPT\02.Mail
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config.example.json config.json
.\.venv\Scripts\python.exe app.py serve
```

Python 명령이 없다면 [Python 공식 배포처](https://www.python.org/downloads/windows/)에서 Python을 설치하세요. `python`이 Microsoft Store 별칭으로 연결되는 경우 `py -3` 또는 설치한 Python 실행 파일의 전체 경로를 사용하세요.

설정 파일이 이미 있다면 복사 명령을 생략합니다. 별도 활성화 스크립트 없이 `.venv\Scripts\python.exe`를 사용하므로 PowerShell 실행 정책 변경이 필요하지 않습니다.

화면 주소: <http://127.0.0.1:18765>. 포트가 사용 중이거나 Windows 예약 범위라면 `config.json`의 `port`를 다른 값으로 바꾸고 앱이 출력한 주소로 접속합니다. 종료는 터미널에서 Ctrl+C입니다.

다음 실행부터는 `run.bat`을 사용해도 됩니다. 서버가 켜진 뒤 출력된 주소를 브라우저에서 여세요.

## 3. 가상 메일로 전체 흐름 확인

실제 메일과 섞이지 않도록 먼저 별도 터미널에서 다음 명령으로 실습 화면을 엽니다.

```powershell
.\.venv\Scripts\python.exe app.py --config config.demo.json serve
```

주소는 <http://127.0.0.1:18766>이며 실습 모드의 자동 Outlook 수집은 꺼져 있습니다. 가상 메일 추가 버튼은 왼쪽 아래 **사용 방법·가져오기** 안에 있습니다.

1. **사용 방법·가져오기 → 가상 메일 추가**를 누릅니다.
2. 메일 5건, 확인 대기 3건인지 확인합니다. 다른 사람 업무와 공지에는 내 업무 제안이 생기지 않습니다.
3. 확인함에서 알파 프로젝트의 CREATE 제안을 승인합니다.
4. 알파 UPDATE 제안의 **대상 업무**에서 `검토 자료 제출 (알파)`를 선택하고 승인합니다.
5. 베타의 `회의 안건 정리` CREATE를 승인합니다.
6. **내 업무**에서 알파 기한이 변경됐는지 확인합니다.
7. 실습으로 베타 업무 상태를 완료로 바꾸고 **변경 저장**을 누릅니다.
8. **근거 검색**에서 `협력사`를 검색합니다. 최초 요청과 변경 메일, 관련 변경 이력이 함께 나옵니다.
9. **주간 보고**에서 최근 7일로 보고서를 만듭니다. 완료 1건, 진행 1건인지 확인하고 다운로드합니다.
10. **변경 이력**과 **처리 로그**에서 업무 전후 상태와 실행 단계를 확인합니다.
11. 가상 메일을 다시 수집하면 같은 날짜의 메일은 중복 5건으로 표시됩니다.

가상 메일 ID에는 날짜가 들어 있으므로 다른 날 실행하면 새 실습 메일입니다. 규칙 모드의 요약은 본문의 앞부분을 보여주는 실습 기능입니다.

## 4. 본인 계정 설정과 실습 데이터 분리

앱을 종료한 뒤 `config.json`을 편집합니다.

```json
{
  "user_email": "본인@회사도메인",
  "identity_mode": "manual",
  "aliases": ["본인별칭@회사도메인"],
  "data_dir": "data/company",
  "engine": "rules",
  "ollama_model": "",
  "port": 18765,
  "collection_limit": 50,
  "outlook_auto_sync": true,
  "outlook_sync_minutes": 10,
  "groupware": {}
}
```

위 JSON은 설명용입니다. 그룹웨어 수집 시에는 예제 파일의 `groupware` 설정을 보존해 값을 채워야 합니다. 이메일은 실제 주소여야 합니다. 별칭은 본인의 주소만 넣습니다.

실습 DB와 실제 메일 DB는 서로 다른 `data_dir`로 운영하세요. 앱에 사용자를 바꿔 로그인하는 기능은 없습니다. 계정 전환 시 데이터 폴더도 분리해야 합니다.

프로그램은 데이터 폴더를 최초 사용한 이메일에 연결합니다. 다른 이메일로 같은 폴더를 열면 거부하므로 새 `data_dir`을 지정하세요.

## 5. EML과 JSON 가져오기

원본 파일을 보존한 상태로 가져옵니다.

```powershell
.\.venv\Scripts\python.exe app.py import "D:\내메일\sample.eml"
.\.venv\Scripts\python.exe app.py import "D:\내메일\eml폴더"
.\.venv\Scripts\python.exe app.py import "D:\내메일\messages.json"
```

폴더는 바로 아래의 `*.eml`만 읽으며 재귀 순회하지 않습니다. EML의 Date 헤더에는 시간대가 필요합니다. 첨부파일은 분석하지 않습니다.

JSON 형식 예:

```json
[
  {
    "id": "unique-message-001",
    "thread_id": "project-a-thread-01",
    "subject": "[알파] 검토 요청",
    "sender": "lead@example.com",
    "to": "me@example.com",
    "cc": "",
    "sent_at": "2026-11-04T09:00:00+09:00",
    "body": "me@example.com 담당자님, 업무: 검토 자료 제출; 2026-11-06까지 준비해주세요.",
    "source": "manual-json"
  }
]
```

`to` 또는 `cc`에 설정한 본인 주소가 있어야 합니다. 같은 `id`의 본문을 바꾸면 충돌로 거부됩니다. 수정본 메일은 고유한 새 ID로 가져옵니다.

웹 화면에서는 4.9MB 이하 JSON 파일을 가져올 수 있습니다. EML은 CLI를 사용합니다. CLI는 데이터가 많은 파일도 읽지만 한 번에 소량으로 처리하는 것을 권장합니다.

## 6. Classic Outlook 수집

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-collectors.txt
.\.venv\Scripts\python.exe app.py outlook-status
.\.venv\Scripts\python.exe app.py collect outlook --preview
.\.venv\Scripts\python.exe app.py collect outlook
.\.venv\Scripts\python.exe app.py collect outlook --start 2026-09-01 --end 2026-09-30
```

`--preview`는 메일을 읽고 건수만 출력하며 앱 DB에 메일·업무를 저장하지 않습니다. 정상 확인 후 저장 명령을 실행하세요.

수집 조건:

- Windows Classic Outlook에서 본인 계정으로 정상 로그인.
- `config.json`의 본인 SMTP 주소가 Outlook 계정과 일치.
- 해당 계정 DeliveryStore의 받은편지함만 조회.
- 기본은 현재부터 30일 전까지 수신한 메일. Outlook Restrict로 기간 필터 후 조회.
- 이전 메일은 `--start`와 `--end`를 함께 지정. `collection_limit`은 그룹웨어에만 적용.
- 이미 저장된 메일은 ID만 확인하고 본문을 다시 읽지 않음. 수집은 오래된 순서로 처리.
- 본인이 To/Cc에 없는 메일은 제외. 배포목록으로만 도착한 메일은 본인 별칭을 명시적으로 설정하지 않으면 제외될 수 있음.

공유 사서함·다른 사람 계정·하위 폴더는 수집하지 않습니다. Outlook 보안 알림이 나타날 수 있습니다. 알림을 끄는 기능은 구현하지 않았습니다.

New Outlook에서는 COM 수집을 사용하지 않습니다. Outlook 웹 화면에 맞춘 그룹웨어 선택자 설정 또는 EML 파일 가져오기를 사용하세요.

## 7. 그룹웨어·Outlook 웹 화면 수집

### 준비

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-collectors.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

이 기능은 DOM 어댑터입니다. 회사 그룹웨어 이름·URL·화면 구조가 아직 없으므로 기본 예제 선택자는 실제 제품에 맞춰 교체해야 합니다. Outlook 웹도 전용 고정 선택자가 포함된 상태는 아닙니다.

### 선택자 설정

브라우저 개발자 도구의 요소 검사로 다음 필드를 확인합니다. 본문이나 인증 쿠키를 외부 사이트에 복사할 필요는 없습니다.

| 설정 | 의미 | 조건 |
|---|---|---|
| url | 본인 받은편지함 시작 주소 | HTTPS |
| allowed_origin | 허용 출처 | 스킴+호스트+필요 시 포트, url과 일치 |
| account_selector | 현재 계정 이메일 요소 | 로그인 후 정확히 1개 |
| account_attribute | 이메일을 읽을 속성 | 빈 문자열이면 요소 텍스트 |
| row_selector | 현재 목록의 메일 행 | 메시지마다 하나 |
| id_attribute | 고유 메일 ID 속성 | 재실행해도 변하지 않는 값 |
| thread_attribute | 스레드 ID 속성 | 없으면 단일 메일로 처리 |
| subject_selector | 제목 | 메일마다 정확히 1개 |
| sender_selector | 보낸 사람 | 실제 주소 표시 권장 |
| to_selector | 받는 사람 | 본인 SMTP 주소가 보여야 함 |
| cc_selector | 참조 | 요소가 없어도 허용 |
| date_selector | 발송 시각 | ISO 날짜+시간대 |
| date_attribute | 날짜 속성 | 예: datetime, 빈 값이면 요소 텍스트 |
| body_selector | 본문 텍스트 요소 | 메일마다 정확히 1개 |

`open_messages=false`(기본): 각 행 안에 제목·주소·날짜·본문 요소가 있는 화면용입니다. 선택자는 메일 행을 기준으로 찾습니다.

`open_messages=true`: 각 행을 눌러 상세 화면을 연 뒤 페이지 전체에서 필드를 찾습니다. 목록과 상세를 같이 보여주는 화면에 적합합니다. 목록으로 돌아가야 한다면 `back_selector`에 돌아가기 버튼 선택자를 추가합니다.

```json
"open_messages": true,
"back_selector": "button.back-to-list"
```

예제 속성명은 임의 예시이므로 실제 화면에서 확인한 선택자로 바꿔야 합니다. iframe 내부·가상 스크롤·동적 ID·한국어 날짜만 있는 사이트는 해당 사이트용 수집기 수정이 필요합니다. 선택자 설정만으로 모든 유형을 지원하지 않습니다.

### 실행

```powershell
.\.venv\Scripts\python.exe app.py collect groupware --preview
.\.venv\Scripts\python.exe app.py collect groupware
```

1. 전용 Chromium 창이 열립니다.
2. 직접 로그인·MFA를 완료하고 본인 받은편지함을 엽니다.
3. 터미널로 돌아와 Enter를 누릅니다.
4. 계정과 출처 검사를 통과하면 현재 목록을 제한 건수까지 읽습니다.
5. 완료 후 수집 브라우저가 닫힙니다. 앱 화면에서 새로고침합니다.

페이지 넘김은 현재 구현하지 않았습니다. 수집 대상은 현재 렌더링된 목록입니다. 메일 행 클릭으로 그룹웨어의 읽음 상태가 바뀔 수 있습니다. 설정 오류가 나면 저장 전에 종료될 수 있으므로 선택자를 먼저 소량으로 검증하세요.

로그인 세션은 `data_dir/browser-profile`에 남을 수 있습니다. 이 폴더에는 인증 상태가 포함되므로 공유·Git 업로드·이메일 첨부를 하지 않습니다. 로그인 만료 시 다시 직접 로그인합니다.

## 8. 로컬 AI 분석 사용

[Ollama 공식 사이트](https://ollama.com/)에서 설치하고, PC 사양에 맞는 한국어 처리 모델을 로컬에 준비합니다. 원격 전용 모델 대신 로컬에서 실행되는 모델을 사용하세요. 앱은 모델을 자동 다운로드하지 않습니다.

```powershell
ollama list
```

목록에 나온 정확한 로컬 모델 이름으로 설정합니다.

```json
"engine": "ollama",
"ollama_model": "여기에_로컬_모델_이름"
```

앱을 다시 시작하면 역할별 프롬프트가 순차 호출됩니다. 주소는 코드에서 로컬 `127.0.0.1:11434`로 고정되어 있습니다. 모델이 호출을 지원해야 하며 Ollama가 실행 중이어야 합니다.

기존에 수집한 동일 ID는 중복으로 건너뜁니다. 규칙 모드와 AI 모드를 비교하려면 서로 다른 데이터 폴더를 사용하세요.

모델의 JSON 오류·원문에 없는 근거·검증 불통과는 메일별 실패로 표시됩니다. 모델 접속 장애는 실행 실패입니다. 원본 EML/JSON은 유지되므로 문제를 확인하고 다시 가져올 수 있습니다. 이미 저장된 메일은 다시 생성되지 않습니다.

## 9. 검색과 주간 보고 CLI

```powershell
.\.venv\Scripts\python.exe app.py search "알파"
.\.venv\Scripts\python.exe app.py report
.\.venv\Scripts\python.exe app.py report --start 2026-11-01 --end 2026-11-04
.\.venv\Scripts\python.exe app.py wiki
```

검색은 질문의 단어를 OR 조건으로 찾고, 관련 스레드를 추가 조회합니다. 자연어 질문 전체의 의도를 해석해 검색식을 재작성하는 기능은 없습니다. 프로젝트명이나 메일에 있는 핵심 단어를 사용하는 것이 좋습니다. 임베딩 검색·GraphRAG는 이후 확장 범위입니다.

보고 기본 기간은 오늘 포함 최근 7일입니다. 종료일 이후 상태는 보고에 섞이지 않도록 이벤트를 재생합니다. 저장 위치는 `data_dir/reports/`이며 동일 기간에 다시 생성하면 별도 버전입니다.

## 10. 금요일 보고 예약

`scripts/weekly_report.ps1`은 웹 화면이 꺼져 있어도 기본 최근 7일 보고를 생성합니다. PC가 켜져 있어야 하며 로컬 모델 모드에서는 Ollama도 켜져 있어야 합니다.

Windows **작업 스케줄러 → 기본 작업 만들기**에서:

- 트리거: 매주 금요일, 원하는 시각(예: 17:00).
- 프로그램: `powershell.exe`.
- 인수: `-NoProfile -File "D:\99.GPT\02.Mail\scripts\weekly_report.ps1"`.
- 시작 위치: `D:\99.GPT\02.Mail`.
- 본인 Windows 계정으로 실행.

환경에서 PowerShell 스크립트 실행을 제한하면 Python을 직접 예약합니다.

- 프로그램: `D:\99.GPT\02.Mail\.venv\Scripts\python.exe`.
- 인수: `app.py report`.
- 시작 위치: `D:\99.GPT\02.Mail`.

예약 등록 자체는 자동 수행하지 않았습니다. 보고서만 생성하며 자동 발송은 하지 않습니다. 그룹웨어 로그인은 대화형이므로 무인 예약용이 아닙니다. Outlook은 앱 실행 중 10분마다 최근 30일을 자동 수집합니다. 앱이 꺼져 있을 때는 동작하지 않습니다.

## 11. 저장·백업·오류 대응

- 앱과 수집 명령을 종료한 뒤 `data_dir` 전체를 회사가 허용한 저장소에 백업합니다.
- 로그인 세션을 백업하지 않으려면 `browser-profile`을 제외합니다.
- 원문은 `mailbrain.sqlite3`, 위키와 보고는 같은 데이터 폴더 안에 있습니다.
- 저장 암호화는 미구현입니다. Windows 계정 보호와 디스크 보안 정책을 적용합니다.
- 확인함에 대상이 없으면 신규 업무를 먼저 승인하고 다시 대상을 선택합니다.
- 모델 처리 중 단일 서버 응답이 지연될 수 있습니다. 처리가 끝날 때까지 기다린 뒤 새로고침합니다.
- 업무 저장은 됐는데 위키 오류가 나면 업무 이력을 확인한 후 `app.py wiki`를 실행합니다.
- 실서버 선택자 오류와 계정 오류는 처리 로그 이전의 수집 단계에서 터미널에 표시됩니다.
- `--preview`도 메일을 읽고 브라우저 프로필을 생성할 수 있지만 업무 DB 저장은 하지 않습니다.

# 최신 실행 안내

`run.bat`은 브라우저를 자동으로 열고 같은 앱의 중복 실행을 재사용합니다. 포트가 다른 프로그램이나 이전 버전에서 사용 중이면 다음 빈 포트를 선택합니다. `WinError 10048`이 보였던 경우 최신 `run.bat`을 다시 실행해 콘솔의 주소를 사용하세요.
