# 토픽 정리·일자별 RAG·주간보고 업데이트

## v0.1 백업

변경 전 코드·설정·수집 데이터는 `backups/v0.1/`에 보관했습니다. 원본 파일 52개, 약 6.6MB이며 가상환경·Git·캐시는 제외했습니다. SQLite 백업 API로 일관된 스냅샷을 만들고 무결성 검사를 통과했습니다. `backup_manifest.json`에 파일별 SHA-256을 기록했고 `복원안내.md`에 복원 방법을 남겼습니다. 이 백업은 업데이트에서 수정하지 않았습니다.

## 토픽별 메일과 확인함

- 같은 Outlook ConversationID를 우선 묶습니다. 회신의 ID가 달라도 `Re:`, `FW:`, 반복된 `[외부메일]`을 제거한 제목이 같으면 묶습니다. 짧은 공통 제목은 합치지 않습니다.
- 토픽과 하위 메일은 최신 수신일순입니다. 기존 메일 409건의 실제 수신 시각을 Outlook 메타데이터로 보완했습니다. 본문은 다시 읽거나 덮어쓰지 않았습니다.
- 실제 자료는 213개 토픽으로 표시됩니다. 원문 409건과 승인 대기 후보는 보존합니다.
- 토픽을 펼치면 메일별 새 본문 요약과 원문 보기가 나타납니다. 과거 회신 인용문은 요약에서 제외하지만 원문에는 남깁니다.
- 확인함에서는 **업무 후보 펼치기**를 한 번 더 열어 승인·제외·대상 연결을 할 수 있습니다.
- 수신일이 없는 EML 등은 발송일로 대체하고 표시합니다.

## 업무 히스토리 — RAG

왼쪽 **업무 히스토리**에서 질문·기간·토픽을 지정합니다. 예: `QA 서버 카피 일정 변경`, `협력사 지연 이유`, `예산 검토 진행 내용`.

메일 새 본문과 업무 변경 이벤트를 청크로 나눠 로컬 SQLite FTS5에 색인합니다. 한국어 부분어절·동의어를 활용한 BM25로 근거를 검색하고 같은 토픽의 전후 메일로 확장합니다. 기간·토픽 필터는 확장에도 적용합니다. 자료가 바뀌면 색인을 재구성하고 이후 검색에서는 재사용합니다.

기본은 **근거 추출형 RAG**입니다. 신경망 임베딩이나 LLM이 없어도 검색된 문장과 일자별 타임라인을 보여줍니다. `engine=ollama`와 로컬 모델을 설정하면 검색 근거로 생성형 답변을 만듭니다. 답변의 출처 ID가 실제 검색 결과에 있는지 검사합니다. 현재는 BM25 기반이며 의미 임베딩 검색·GraphRAG는 아닙니다.

메일 수신일과 업무 변경일을 구분합니다. 미승인 메일도 검색되지만 수신을 업무 완료로 간주하지 않습니다. 최신 최대 120개 근거를 표시하므로 과거 내역은 기간을 좁혀 조회하세요. 원문 보기는 유지됩니다.

## 주간보고

참고 PDF처럼 **구분 / 업무 내용(금주) / 차주 / 비고** 4열로 구성합니다.

구분: SAP ERP 개선 과제, SAP ERP 이슈 및 조치, SAP ERP 운영 유지보수 관리, AI 데이터 업무 지원, IFRS18 업무 지원, 펌뱅킹, 상시업무. 제목·키워드 기반 초안 분류이므로 검토 후 확정합니다.

- 금주: 기간 내 수신 토픽의 최신 요약과 승인된 업무 변경.
- 차주: 종료일 다음 7일에 기한이 있는 미완료 확정 업무. 근거 없는 계획은 만들지 않습니다.
- 비고: 원문 링크와 확인 필요 사항.
- 분류별 최근 8개 메일 토픽을 기본으로 요약하고 초과 수는 명시합니다. 전체 자료는 히스토리에서 검색합니다. `report_topics_per_category`로 1~30개를 지정할 수 있습니다.
- 로그인 코드·인증 링크 알림은 보고서에서 제외합니다. 메일 원문은 삭제하지 않습니다.
- 완료 실적은 메일 건수가 아닌 승인된 완료 이벤트로 집계합니다.
- **PDF 다운로드**와 Markdown 다운로드를 제공합니다. PDF 근거 링크는 로컬 앱 실행 중 열립니다.

긴 표는 페이지별 머리글을 반복하고 토픽별 행으로 나눕니다. 첨부 PDF의 업무 내용 자체를 복사한 보고서는 아닙니다.

## 실행

이전 서버를 종료하고 `run.bat`을 다시 실행하세요. 프롬프트는 직접 실행할 필요가 없습니다. 현재 가상환경에는 PDF 생성용 reportlab을 설치했습니다. 다른 PC는 `pip install -r requirements.txt`로 준비합니다.

시작할 때 기존 DB에 수신 시각과 보고서 구조 컬럼을 추가합니다. 메일 원문·업무·변경 이벤트는 삭제하지 않습니다.
