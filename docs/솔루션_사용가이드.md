# 메일 기반 해결 방안과 간결한 화면

## 사용하는 방법

1. `run.bat`을 실행합니다. 같은 앱이 실행 중이면 기존 화면을 자동으로 엽니다.
2. **내 업무**에서 업무 제목을 펼치고 **해결 방안 보기**를 누릅니다.
3. 확인함 또는 수집한 메일에서는 토픽을 펼쳐 **이 대화의 해결 방안 보기**를 누릅니다.
4. 상황에 맞춘 검토 제안, 다음 행동, 확인 질문을 읽습니다. **근거 1** 같은 버튼으로 원문을 대조합니다.
5. 참고한 메일과 검토 범위, 실행 전 확인사항은 아래에서 펼칠 수 있습니다.
6. 같은 내용을 다시 열면 저장된 제안을 보여줍니다. 강제로 재검토하려면 **다시 검토**를 누릅니다.

제안만 생성하며 업무 상태·기한을 바꾸거나 메일을 보내지 않습니다. 완료·삭제·복원은 기존 버튼으로 직접 처리합니다. Teams 알림과 다른 수집 제외 메일은 제안 근거에서도 제외합니다. 제외된 원문만 연결된 업무에는 제안을 만들지 않습니다.

## 기본 모드와 AI 모드

현재 기본값 `engine=rules`는 본문의 복제·복구, 장애, 일정, 자료 요청 등의 표현을 읽어 관련 검토 절차를 제시합니다. 실제 원인 분석 결과를 생성하는 LLM은 아닙니다. 근거의 원문 인용과 점검 질문을 함께 제공합니다.

로컬 Ollama가 이미 준비되어 있다면 `config.json`의 `engine`을 `ollama`, `ollama_model`을 설치된 모델명으로 설정한 뒤 앱을 재시작합니다. 모델 설치·선정은 회사 정책과 PC 메모리에 맞춰 진행해야 합니다. 이 변경은 수집·검색 등 기존 AI 역할에도 적용됩니다. 실제 모델 응답 품질은 사용 환경에서 별도로 검증해야 합니다.

AI는 `main_prompt + prompts/common.md + prompts/07_solution.md`와 연결된 메일을 입력받습니다. 연결 주소는 기존과 같은 `127.0.0.1:11434`이며 시스템 프록시를 사용하지 않습니다. 외부 AI API는 추가하지 않았습니다. 모델 실패나 잘못된 근거 ID가 있으면 화면에 이유를 알리고 **메일 기반 검토 가이드**를 표시합니다. 근거 ID 검사는 내용 전체의 사실성을 보장하지 않으므로 실행 전 원문을 확인하세요.

## 검토 범위와 저장

- 토픽: 수집이 허용된 같은 대화의 메일을 함께 검토합니다.
- 업무: 최초 출처와 승인·변경 이벤트에 연결된 출처를 찾은 뒤 해당 대화로 확장합니다. 단순히 업무 제목이 비슷하다는 이유로 다른 업무의 메일을 가져오지 않습니다.
- 많은 대화는 최근 12건 이내로 제한하며 최초 업무 근거가 빠지면 마지막 한 건을 교체해 포함합니다. 각 메일의 인용 회신을 제거한 새 본문 최대 2,200자를 사용합니다. 제목·발신자·일시와 일부 원문 인용을 함께 보관합니다.
- 첨부파일, 외부 링크, 운영 시스템의 상태는 분석하지 않습니다. 전체 원문은 기존 원문 보기에서 확인할 수 있습니다.
- `solutions` 테이블에 입력 지문과 제안을 저장합니다. 지문에는 선택된 메일 내용·업무 현재값·엔진·모델명·프롬프트가 포함됩니다. 내용이 달라지면 새 지문의 결과를 저장합니다. 같은 지문의 수동 재검토는 그 결과를 갱신합니다. 따라서 모든 재생성 버전을 영구 보존하는 이력 저장소는 아닙니다.
- 실행 기록에는 성공·실패와 프롬프트 해시가 기록됩니다. 업무 상태 이벤트와 분리되며 실제 업무 원문과 기존 이벤트는 변경하지 않습니다.

## 화면 변경

수집 연결·기간 설정은 상단 **메일 수집**을 펼쳐 사용합니다. 내 업무는 제목·프로젝트·상태·기한 또는 완료일만 먼저 보여줍니다. 제목을 펼치면 해결 방안·원문·완료 처리가 나오고, 상태·기한 수정과 삭제는 한 단계 더 펼쳐서 사용합니다.

검색어와 상태는 항상 보이며, 프로젝트·휴지통·완료일 필터는 **상세 필터**에 모았습니다. 접어도 적용한 조건은 유지되고 적용 건수를 표시합니다. 상세 조건을 모두 해제하려면 **필터 초기화**를 누르세요.

화면 설계는 기존 `design-skills/frontend-design/SKILL.md`를 참고했습니다. 기존 네이비 `#182941`, 본문 `#26364d`, 강조 `#315deb`, 배경 `#f5f7fb`, 완료 `#15805c`를 유지했습니다. Segoe UI·맑은 고딕을 그대로 사용하고 목록은 왼쪽 정렬, 제안은 읽기 폭을 제한한 별도 창에 표시합니다. 기능을 추가하는 대신 목록의 상시 노출 제어를 줄이는 데 집중했습니다.

## 포트 충돌 오류

`WinError 10048`은 같은 주소·포트가 이미 사용 중이라는 뜻입니다. 이제 `run.bat`은 같은 앱을 식별하면 기존 화면을 엽니다. 다른 프로그램이나 다른 코드 버전이면 설정 포트부터 최대 20개 범위에서 빈 포트를 사용합니다. 원래 설정 파일과 다른 프로그램은 변경하지 않습니다.

화면 주소는 콘솔에 표시되며 자동으로 브라우저가 열립니다. 기존 오래된 창에서 계속 작업 중이었다면 저장을 마치고 그 서버 창에서 Ctrl+C로 종료하세요. 포트가 바뀐 새 화면에서는 브라우저 새로고침 후 사용합니다. 모든 후보 포트가 사용 중이면 `config.json`의 `port`를 다른 값으로 지정합니다. 포트 자동 선택은 사내 서버 배포 기능이 아닙니다.
